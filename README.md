# FSK M — ربات فیلم، نسخهٔ ۲، بچ ۴۰۰

این بسته بر اساس فایل `FSK_Movies_Real_Database_Test (1).ipynb` ارسالی شما ساخته شده است.
متن پرامپت تحلیل درخواست، غربالگری و داوری نهایی عیناً حفظ شده است. اندازهٔ بچ در موتور و داوری یکسان و برابر ۴۰۰ است.

## راه‌اندازی روی Render

۱. محتویات این پوشه را در یک مخزن مستقل GitHub بگذارید. تمام فایل‌های `fsk_*.py` نیز لازم‌اند؛ فقط سه فایل اصلی کافی نیست.
۲. در Render یک **Background Worker** بسازید و مخزن را وصل کنید. فایل `render.yaml` نیز تنظیمات Blueprint را دارد.
۳. فرمان ساخت: `pip install -r requirements.txt`
۴. فرمان شروع: `python main.py`
۵. در Environment این مقادیر را تنظیم کنید:

- `TELEGRAM_TOKEN`: توکن ربات فیلم از BotFather. برای روشن ماندن ربات سریال، توکن جداگانه استفاده کنید. هم‌زمان دو برنامه با یک توکن polling نکنند.
- `SUPABASE_URL`
- `SUPABASE_SECRET_KEY`
- `GEMINI_KEY_1` تا `GEMINI_KEY_14`: همان نام‌های قبلی؛ حداقل یک کلید لازم است. مقادیر تکراری فقط یک بار وارد صف می‌شوند.
- اختیاری: `DATA_DIR`؛ پیش‌فرض `./data` است.

کلیدها را داخل کد، مخزن یا فایل requirements نگذارید. این موتور به رمز PostgreSQL نیاز ندارد.

این برنامه Worker است؛ پورت وب و Flask لازم ندارد. فایل آمادهٔ Render از نوع worker است. سرویس را با یک نمونه اجرا کنید؛ چند نمونهٔ polling با یک توکن مناسب نیست.

## تست اولیه

قبل از روشن‌کردن polling، در محیطی که متغیرها و پکیج‌ها تنظیم شده‌اند:

```bash
python smoke_check.py
```

این فرمان فقط فیلم‌ها، کانسپت‌ها و عبارت‌ها را از سوپابیس می‌خواند و تعدادشان را گزارش می‌کند؛ جمینی و تلگرام را فراخوانی نمی‌کند.

برای یک جست‌وجوی واقعی، با مصرف سهمیهٔ جمینی:

```bash
python smoke_check.py --query 'یه فیلم درباره شروع دوباره می‌خوام که کمی طنز داشته باشه'
```

سپس ربات را اجرا کنید، `/start` بزنید، درخواست را بنویسید و تأیید کنید. اولین نتیجه‌ها سه‌تا سه‌تا نمایش داده می‌شوند.

## رفتار موتور

- فقط خواندن `movies`، `movie_concepts` و `movie_special_phrases`؛ هیچ نوشتنی در دیتابیس انجام نمی‌شود.
- همهٔ فیلم‌ها، حتی فیلم‌های بدون تحلیل کامنت، بررسی می‌شوند.
- مدل `gemini-3.5-flash-lite`؛ دو مسیر منطقی غربالگری، هر بچ ۴۰۰ فیلم، حداکثر ۱۰ کاندید از هر بچ. تماس زندهٔ API عمداً فقط یکی در هر لحظه است. از پایان هر تماس، موفق یا ناموفق، تا شروع تماس بعدی حداقل ۳ ثانیه فاصله است. کلید پس از موفقیت هم به کلید بعدی می‌رود؛ پاسخ‌های کش‌شده تماس API ندارند.
- ۷۰ حس‌وحال / ۳۰ داستان؛ اگر داستان خاصی خواسته نشده، ۱۰۰ حس‌وحال.
- حداکثر ۱۰۰ کاندید برای داوری و ۵۰ پیشنهاد نهایی. تطابق نسبی حفظ می‌شود؛ نامناسب حذف می‌شود. IMDb فقط نمایش داده می‌شود.
- هر جست‌وجو محیط مستقل دارد؛ نتیجهٔ اجرای قدیمی قابل انتقال تصادفی به اجرای جدید نیست.
- اگر غربالگری یا داوری کامل نشود، پیشنهاد ناقص به‌عنوان پاسخ نهایی فرستاده نمی‌شود. ارسال مجدد همان درخواست، پاسخ‌های موفق کش‌شده را استفاده می‌کند.
- پایان هر تماس → کلید بعدی با فاصلهٔ حداقل ۳ ثانیه؛ پس از خطای همهٔ کلیدهای قابل استفاده، مکث دوری ۵، ۱۰، ۲۰، ۴۰ و حداکثر ۶۰ ثانیه نیز برقرار است. انتظارهای هم‌زمان با هم هم‌پوشانی دارند؛ حداقل فاصله و Retry-After صریح سرویس رعایت می‌شود. کلید نامعتبر/بدون دسترسی کنار گذاشته می‌شود.
- از لحظهٔ تأیید، فقط درخواست یک کاربر پذیرفته می‌شود؛ کاربران دیگر پیام «فعلا مشغول است.» می‌گیرند و وارد صف نمی‌شوند. به‌محض پایان تمام پاسخ‌های لازم جمینی، قفل مشغول بودن آزاد می‌شود؛ نمایش سه‌تایی نتایج قبلی مانع جستجوی جدید نیست.
- سقف زمانی ۱۵ دقیقه و سقف تعداد تلاش حذف شده است. خطاهای موقت شبکه، شلوغی، سهمیه و JSON با همان فاصله‌ها مجدداً امتحان می‌شوند. داوری ناقص نیز خودکار ادامه پیدا می‌کند. هر تماس HTTP حداکثر ۱۲۰ ثانیه فرصت دارد و پس از timeout دوباره تلاش می‌شود.
- خطای دائمی نام مدل/ورودی یا نامعتبر بودن تمام کلیدها نیازمند اصلاح تنظیمات است؛ در این وضعیت خطای مشخص ثبت می‌شود و ربات از حالت مشغول خارج می‌شود. لغو دستی نیز برقرار است؛ تماس HTTP در حال اجرا ممکن است تا پایان پاسخ/timeout ادامه یابد و تا آن زمان ربات همچنان مشغول است.
- لغو سریع رابط؛ تماس HTTP در حال اجرا ممکن است تا دریافت پاسخ یا timeout خود باقی بماند. پس از لغو، نتیجهٔ آن برای کاربر ارسال نمی‌شود.
- مشخصات هر فیلم در یک خط متن ساده است: کشور، سال، ژانر، نمره، زمان، نام بازیگران بدون پیشوند، و «کارگردان:» همراه نام کارگردان‌ها. اگر متن از سقف کپشن بیشتر شود، مشخصات در پیام متنی همراه پوستر می‌آید.
- پیام خوشامد، شروع، انتظار و آماده‌شدن، جمله‌های کوتاه کردی با رسم‌الخط کردی دارند.
- پیام وضعیت هر دقیقه؛ لاگ تعداد بچ‌ها، زمان‌ها، خطای دسته‌بندی‌شده و کش روی سرور.

## پوستر

تصویر در یک thread جدا دانلود و به‌صورت فایل برای تلگرام ارسال می‌شود. شناسهٔ تصویرِ ارسال‌شده در حافظه برای استفادهٔ بعدی نگه داشته می‌شود. اگر میزبان تصویر HTTP 403 بدهد یا دانلود ناموفق باشد، نتیجه به‌صورت متن با مشخصات و لینک فیلم ارسال می‌شود. این نسخه ادعا نمی‌کند محدودیت دسترسی میزبان پوستر را برطرف کرده است.

## کش و گزارش‌ها

پوشهٔ `data/gemini_cache` پاسخ‌های موفق را بر اساس مدل و متن کامل پرامپت نگه می‌دارد. گزارش هر جست‌وجو در `data/runs` جداست و شامل درخواست، مدل، شناسهٔ دیتاست، گزارش غربالگری و داوری است. این گزارش‌ها را عمومی منتشر نکنید؛ متن درخواست کاربران در آن‌ها وجود دارد.

روی فایل‌سیستم موقت، کش پس از تعویض یا استقرار مجدد سرویس ممکن است از بین برود. برای نگهداری بین استقرارها، `DATA_DIR` را به فضای پایدار متصل‌شدهٔ سرویس تنظیم کنید. خود دیتابیس هیچ تغییری نمی‌کند. داده‌ها هنگام شروع برنامه لود می‌شوند؛ برای دریافت تغییرات جدید دیتابیس، برنامه را مجدداً راه‌اندازی کنید.
